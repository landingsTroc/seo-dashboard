How to verify this without taking anyone’s word for it

Open the page, view source, search for robots

What decides whether Google may index a page is a single line the server sends. For /deloittes-technology-fast-500-t-roc-won/ that line reads:

<meta name="robots" content="index, follow, max-image-preview:large, max-snippet:-1, max-video-preview:-1">

It says index. The same check on all 53 produced the table at the end of this page. Anyone can repeat it in a browser in under a minute per URL, with no tooling and no account.

Why a crawler reported these as blocked

Twenty of them are the press releases we redirected on purpose

In July this team consolidated a set of old press releases and award announcements into /company/, as part of the content prune. Those URLs now answer with a 301 redirect, which is the intended behaviour: the content lives at one strong address instead of twenty weak ones.

A crawl report that lists a 301 as “blocked” is describing the redirect, not a noindex tag. The destination, /company/, is fully indexable. Removing anything here would undo deliberate work and recreate twenty thin pages.

The last-crawled dates on the supplied list run from October 2026 back to October 2025, which is consistent with a report built before or during that consolidation.

The 16 that genuinely carry noindex

Each is blocked for a reason. None is a blog post.

The only entries worth a conversation are the four legal pages and /total-rewards/. Indexing them would be defensible and would change nothing measurable, because nobody searches for them. The other eleven should stay exactly as they are.

The eight that return 404

Seven sit under old /news/ and /accolades/ paths that no longer exist. The eighth, /cdn-cgi/l/email-protection, is not a page at all — it is Cloudflare’s email-obfuscation endpoint, present on every site behind Cloudflare.

A 404 carries noindex by definition. There is nothing to unblock: the page is gone. If any of that content still matters, the fix is a redirect to its replacement, not an index directive.

What would settle it beyond doubt

The evidence above proves these URLs are not blocked. Search Console would additionally prove Google has them, which is a stronger claim:

  • Impressions per URL over 90 days. A URL that collects impressions is indexed. This is the shortest route to an unarguable answer.
  • URL Inspection reports each address as indexed, or names the exact reason it is not.

The dashboard already contains a working Search Console client (scripts/gsc.mjs) that authenticates with a service account, so this needs no new tooling — only that the connection be run. URL Inspection additionally requires the service account to hold owner or full-user permission on the property; restricted access returns performance data only.

Only four URLs on the list could earn an impression at all

Forty-nine of the fifty-three either redirect, are gone, or are blocked on purpose, so zero impressions is the correct and expected reading for every one of them. That leaves four live indexable pages. One, /bringing-value-to-our-clients-a-success-in-jefferson-ga/, collected 45 impressions. The other three collected none over ninety days.

That is not evidence of a block. They are old press releases, and roughly nine in ten posts on this site draw no search traffic at all. A page with nothing anyone searches for earns nothing, whether or not Google has it. The directive those three serve is index, follow, which is the thing the request asked about.

The honest limit of this evidence: Search Console confirms the consolidation is working and that nothing on this list is being suppressed, but for pages with no search demand it can neither prove nor disprove indexation.
